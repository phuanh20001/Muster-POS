# Connecting a Square Terminal Reader

How to pair a real **Square Terminal** or **Square Handheld** for in-person card payments in DreamyCafe.

DreamyCafe uses the **Square Terminal API** in server-driven mode. The shop PC creates a
Terminal checkout and Square pushes it to the paired device (`src/lib/square.js`,
`src/lib/paymentProvider.js`). Card data never touches this app. There is **no reader SDK**
in the browser — pairing is a one-time step in **Admin → Payments**, then every card sale
from the POS uses the saved device id.

**Important:** Do **not** use Square Dashboard → **Device management** → **Add device** →
pick a mode (Standard, Full service, etc.). That flow signs the Terminal into **Square's
own POS**. DreamyCafe needs a **`TERMINAL_API`** pairing code from the app instead.

---

## Prerequisites

1. **Supported hardware** — Square **Terminal** or **Handheld** (AU is supported; currency
   defaults to `AUD` via `SQUARE_CURRENCY`).
2. **Activated Square account** — complete activation at [squareup.com/activate](https://squareup.com/activate)
   before live card payments.
3. **Square Developer application** — create an app at
   [developer.squareup.com](https://developer.squareup.com). The access token needs
   **`DEVICE_CREDENTIAL_MANAGEMENT`** (and payment permissions) for pairing and charges.
4. **Network** — the Terminal connects to Square over Wi‑Fi (or Ethernet where supported).
   It does **not** need to be on the same LAN as the shop PC; it only needs outbound
   internet to Square.
5. **Production credentials** — for a real reader, all three must be **production** and
   must match each other (sandbox token + sandbox location will not pair production hardware).

| `.env` variable | Purpose |
| --- | --- |
| `SQUARE_ENV` | `sandbox` (default) or `production` |
| `SQUARE_ACCESS_TOKEN` | API token from Developer Dashboard (toggle Sandbox / Production) |
| `SQUARE_LOCATION_ID` | Location id for the cafe (Dashboard → Locations, or Locations API) |
| `SQUARE_CURRENCY` | Optional; defaults to `AUD` |
| `SQUARE_DEVICE_ID` | Optional fallback if DB config is missing |

Restart the DreamyCafe server after changing `.env`.

---

## Step 1 — Test in Sandbox first (no physical reader)

Sandbox is for verifying credentials and the charge flow **without** hardware.

1. In Square Developer Dashboard, toggle **Sandbox** and copy the **Sandbox access token**.
2. Set in `.env`:
   - `SQUARE_ENV=sandbox`
   - `SQUARE_ACCESS_TOKEN=<sandbox token>`
   - `SQUARE_LOCATION_ID=<sandbox location id>`
3. Restart the server.
4. **Admin → Payments** (`/admin/terminal`) → set **In-store card provider** to **Square**.
5. Either click **Use sandbox test device id instead**, or paste this magic device id:

   ```
   9fa747a2-25ff-48ee-b078-04381f7c828f
   ```

6. **Save reader** (name stays **`COUNTER`**, **Enabled** on).
7. **Test charge $1.00** — should succeed with no tap (sandbox auto-completes).

Optional scripts (dev server on `localhost:3000` for app-stack and online):

```bash
node --env-file=.env scripts/test-square-sandbox.js
node --env-file=.env scripts/test-square-app-stack.js
node --env-file=.env scripts/test-square-online.js
node --env-file=.env scripts/test-square-cancel-charge.js
```

**Pair Square Terminal** is disabled in sandbox — it will show an error if you try to pair
physical hardware while `SQUARE_ENV` is not `production`.

---

## Step 2 — Switch to Production

When you are ready for a real Terminal:

1. In Developer Dashboard, toggle **Production** and copy the **Production access token**
   (`sq0atp-…`).
2. Copy your **production location id** (Square Dashboard → **Account & Settings** →
   **Business** → **Locations**).
3. Update `.env`:
   - `SQUARE_ENV=production`
   - `SQUARE_ACCESS_TOKEN=<production token>`
   - `SQUARE_LOCATION_ID=<production location id>`
4. Restart the DreamyCafe server.
5. Run `node --env-file=.env scripts/verify-square-production-ready.js` — all lines should show **OK** before pairing hardware.

All three values must be from the **same** environment. Mixing sandbox token with
`SQUARE_ENV=production` will fail.

---

## Step 3 — Prepare the physical Terminal

1. Power on the Terminal and connect it to **Wi‑Fi**.
2. Complete any firmware updates Square prompts for.
3. Leave it at the **sign-in** screen — do not sign into Square's built-in POS modes via
   the Dashboard "Add device" wizard.

The Terminal must be at the **same location** as `SQUARE_LOCATION_ID` in `.env`.

---

## Step 4 — Pair via DreamyCafe (not the Square Dashboard)

Pairing uses a **short code** generated by DreamyCafe. You enter that code **on the
Terminal**, not in the Square Device ID field.

1. Open **Admin → Payments** on the shop PC (Admin PIN required).
2. Set **In-store card provider** to **Square**.
3. Click **Pair Square Terminal**.
4. DreamyCafe displays a **short pairing code** (about six characters) and a countdown
   (~5 minutes to complete).
5. On the **physical Terminal**:
   - Sign-in screen → **Device code** (not "Sign in with Square account" for POS mode)
   - Enter the short code from DreamyCafe
6. Wait on the Admin page — it polls automatically. When status is **PAIRED**, the long
   **device UUID** fills into **Square Device ID**.
7. Click **Save reader**.
8. Click **Test charge $1.00** and complete a real tap on the Terminal.

### Two different values (easy to confuse)

| What | Example | Where it goes |
| --- | --- | --- |
| **Pairing code** (short) | `JHHYHH` | Enter **on the Square Terminal** |
| **Device id** (UUID) | `9fa747a2-25ff-48ee-b078-04381f7c828f` | **Square Device ID** field in DreamyCafe (auto-filled after pairing) |

You never paste the short code into the Square Device ID box.

---

## Step 5 — Configure reader settings

On **Admin → Payments**:

| Field | Value |
| --- | --- |
| Name | `COUNTER` (default — do not change) |
| Label | e.g. `Front counter` |
| Square Device ID | Filled by pairing, or paste from Square Dashboard → Devices |
| Enabled | ✓ |
| In-store provider | **Square** |

The charge flow resolves the reader named `COUNTER` by default (`resolveSquareDeviceId('COUNTER')`).
Alternatively set `SQUARE_DEVICE_ID` in `.env` as a fallback.

**Online orders** use a separate setting (**Online order provider**). Changing in-store to
Square does not change customer `/order` checkout unless you set `onlineProvider` too.

## Go-live notes

- **Live test charge is real money** when `SQUARE_ENV=production`.
- **Brand blocking does not apply on Square** — blocked brands in Admin → Payments only
  affect channels where Stripe is active. Square auto-captures; there is no auth-then-void.
- **Card surcharge** still applies server-side on card payments (POS and online).
- **Refunds** route by `Order.paymentProvider` — orders taken on Square refund through
  Square even if you later switch the active in-store provider back to Stripe.
- **Split card legs** each charge the Terminal independently; payment refs are comma-joined
  in `Order.paymentIntentId`.

## Quick checklist

1. Sandbox: test with magic device id + Test charge $1.00
2. Activate Square account for live payments
3. `.env` → `SQUARE_ENV=production`, production token + location id
4. Restart server
5. Terminal on Wi‑Fi at the correct location
6. Admin → Payments → **Pair Square Terminal** → enter code on device
7. Save reader (`COUNTER`, Enabled)
8. Test charge $1.00 on real hardware → done

## Troubleshooting

| Problem | What to check |
| --- | --- |
| **"Square Sandbox cannot pair a physical Terminal"** | Set `SQUARE_ENV=production` and production credentials, or use the sandbox test device id for testing only. |
| **Pair Square Terminal does nothing / API error** | Token needs `DEVICE_CREDENTIAL_MANAGEMENT`. `SQUARE_LOCATION_ID` must be set. Restart after `.env` changes. |
| **Code expired** | Pairing codes last ~5 minutes. Click **Pair Square Terminal** again for a new code. |
| **Paired but charge fails** | Confirm **In-store provider** is **Square**. Reader name is `COUNTER`, **Enabled**, and `squareDeviceId` is saved. |
| **"No payment terminal configured"** | `squareDeviceId` is blank, reader is disabled, or name is not `COUNTER`. |
| **Used Square Dashboard "Add device"** | Wrong flow — that runs Square POS on the device. Unpair if needed, then use DreamyCafe **Pair Square Terminal**. |
| **Device list empty in Admin** | Token/location mismatch (sandbox vs production). Log in with Admin or Manager PIN for device listing. |
| **Charge never completes on reader** | Terminal offline or wrong Wi‑Fi. Check Square Dashboard → **Devices** for online status. |

## Verifying fees & payouts

To check Square's actual processing fees and bank payouts against your recorded
sales, run (read-only — never refunds or edits):

```bash
node --env-file=.env scripts/reconcile-square.js
node --env-file=.env scripts/reconcile-square.js --from=2026-06-01 --to=2026-06-26
```

It reconciles `paymentProvider=SQUARE` orders against Square's `payments.get`
(amount match + actual fees + net) and lists recent SENT/PAID payouts. Cash and
online-Stripe sales are excluded by design. Listing payouts needs `PAYOUTS_READ`
on the access token.
